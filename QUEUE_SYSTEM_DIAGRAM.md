## 🛠️ 关键代码逻辑

### 队列检查逻辑 (queue_edm.sh)
```bash
# 检查当前运行任务数
row=$(wc -l running.queue | awk '{print $1}')

if [[ $row -lt $MAX_CONCURRENT ]]; then
    # 有空闲槽位
    echo "$email $timeVar" >> running.queue
    bash EDM.sh "$email" "$timeVar"
else
    # 槽位已满
    echo "$email $timeVar" >> waiting.queue
    echo "Task queued at position $(wc -l waiting.queue)"
fi
```

### 清理和调度逻辑 (cleanup_and_next)
```bash
cleanup_and_next() {
    # 1. 删除已完成任务
    sed -i "/$job_id/d" running.queue

    # 2. 检查等待队列
    rowNew=$(wc -l waiting.queue | awk '{print $1}')

    if [[ $rowNew -gt 0 ]]; then
        # 3. 取出第一个等待任务
        cmdLineNew=$(head -n 1 waiting.queue)
        sed -i '1d' waiting.queue

        # 4. 启动新任务
        bash queue_edm.sh "$email_new" "$timevar_new" &
    fi
}
```

## 🎯 关键设计决策

### 为什么使用文件队列而不是数据库？
✅ **简单性**：无需安装数据库
✅ **轻量级**：适合小规模部署
✅ **可调试**：直接cat查看状态
✅ **原子性**：文件操作足够可靠

### 为什么使用trap机制？
✅ **可靠性**：确保清理函数一定执行
✅ **异常处理**：脚本被kill也能清理
✅ **自动调度**：任务完成自动启动下一个

### 为什么默认MAX_CONCURRENT=1？
✅ **资源保护**：EDM模型很消耗GPU/CPU
✅ **稳定性**：避免OOM (内存不足)
✅ **可预测**：单任务性能稳定
